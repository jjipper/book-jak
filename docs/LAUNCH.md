> 코드로 끝낼 수 없는, **사람이 직접 해야 하는 일**만 모았다. 순서대로 진행하면 된다.
>
> **면책** — 이 문서와 `/terms`·`/privacy` 페이지의 문구는 참고용 초안이며 법률 자문이 아니다.
> 실제 서비스 개시 전 법률 전문가의 검토를 받는 것을 권장한다.

## 0. 먼저 채워야 할 값

`src/app/(main)/privacy/page.tsx`와 `terms/page.tsx`에 `{{ }}` 로 남겨둔 자리다. 카카오 검수 제출 전에 반드시 채운다.

| 플레이스홀더 | 설명 |
|---|---|
| `{{사업자명}}` | 운영 주체. 사업자등록이 없으면 팀명/개인명 |
| `{{대표자명}}` `{{사업자등록번호}}` `{{사업장 주소}}` | 사업자등록이 있는 경우만. 없으면 해당 문장 삭제 |

`src/app/(main)/contact/page.tsx`의 문의 이메일이 현재 `jjipper7@gmail.com`(회사 메일)로 되어 있다. 서비스 전용 주소로 바꿀지 결정한다.

## 1. 도메인 · 환경변수 (리드타임: 당일 ~ 1일)

### 도메인
1. 도메인 구입 → Vercel 프로젝트에 연결 → DNS 전파 대기(보통 수십 분, 최대 48시간).
2. 도메인이 확정돼야 카카오 Redirect URI, Supabase Site URL, OG `metadataBase`를 모두 한 번에 세팅할 수 있다. **가장 먼저 한다.**

### 프로덕션 환경변수 (Vercel > Settings > Environment Variables)

| 키 | 값 | 노출 |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | `https://실서비스도메인` | 공개 (OG·sitemap·robots의 절대 URL 기준) |
| `NEXT_PUBLIC_SUPABASE_URL` | 프로덕션 Supabase 프로젝트 URL | 공개 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 프로덕션 anon key | 공개 (RLS로 보호되는 키) |
| `KAKAO_REST_KEY` | 카카오 REST API 키 | **서버 전용** |
| `ALADDIN_TTB_KEY` | 알라딘 TTB 키 | **서버 전용** |

- `NEXT_PUBLIC_SITE_URL`을 빠뜨리면 Vercel 배포 URL(`VERCEL_PROJECT_PRODUCTION_URL`)로 폴백하고, 로컬에서는 `http://localhost:3000`이 된다. OG 이미지 URL이 절대경로여야 카카오톡·트위터가 읽으므로 실도메인으로 반드시 채운다.
- `KAKAO_REST_KEY`, `ALADDIN_TTB_KEY`는 `NEXT_PUBLIC_` 접두사를 **절대 붙이지 않는다.** 붙이면 브라우저 번들에 노출된다.

## 2. Supabase 프로덕션 분리 (리드타임: 반나절)

개발과 프로덕션은 **별도 프로젝트로 분리**한다. 같은 프로젝트를 쓰면 테스트 계정·더미 게시물이 실서비스에 섞이고, 스키마 실험이 실데이터를 깬다.

1. Supabase에 새 프로젝트 생성 (리전: Seoul 권장 — 지연시간 + 국외이전 고지 단순화).
2. `supabase/schema.sql` 전체를 SQL Editor에 붙여넣고 Run.
3. Authentication > URL Configuration
   - Site URL: `https://실서비스도메인`
   - Redirect URLs: `https://실서비스도메인/auth/callback` (프리뷰 배포를 쓰면 `https://*.vercel.app/auth/callback`도 추가)
4. Authentication > Providers > Kakao 활성화 후 카카오 REST API 키와 Client Secret 입력 (3절에서 발급).

### RLS 실제 검증 방법

스키마에 RLS는 걸려 있지만 **"걸려 있다"와 "동작한다"는 다르다.** 배포 전 아래를 직접 확인한다.

1. 테스트 계정 A, B 두 개로 로그인.
2. A로 리뷰·토론 글·모임을 하나씩 생성.
3. B 세션에서 A의 데이터를 수정/삭제 시도 → **실패해야 한다.**
   - 브라우저 콘솔에서: `await sb.from('ratings').delete().eq('id','<A의 레코드 id>')` → `count: 0` 또는 에러.
4. 로그아웃 상태(anon)에서 insert 시도 → 거부되어야 한다.
5. `blind_reactions`는 본인만 조회 가능하도록 되어 있다. B 세션에서 select 해서 A의 행이 안 나오는지 확인.
6. Supabase 대시보드 > Advisors > Security 에서 RLS 미적용 테이블 경고가 없는지 확인.

> 주의: `increment_post_like` / `decrement_post_like`는 `security definer`라 RLS를 우회한다. 임의의 post id로 호출해 좋아요 수를 조작할 수 있으므로, 남용이 보이면 함수에 호출자 검증을 추가한다.

## 3. 카카오 로그인 실서비스 전환 (리드타임: 영업일 3~5일, 여유 두고 1주)

**이 단계가 전체 런칭 일정의 임계경로다. 도메인이 정해지는 즉시 착수한다.**

### 3-1. 앱 생성 및 플랫폼 등록 (당일)
1. [카카오 디벨로퍼스](https://developers.kakao.com) > 내 애플리케이션 > 애플리케이션 추가.
2. 앱 설정 > 플랫폼 > Web > 사이트 도메인에 `https://실서비스도메인` 등록.
3. 제품 설정 > 카카오 로그인 > 활성화 ON.
4. **Redirect URI 등록** — Supabase를 통해 로그인하므로 카카오에 등록할 주소는 **앱 도메인이 아니라 Supabase 콜백**이다:
   ```
   https://<프로젝트ref>.supabase.co/auth/v1/callback
   ```
   앱 자체의 `/auth/callback`은 Supabase의 Redirect URLs에 등록한다(2절 3번). 이걸 헷갈리면 `KOE006` 오류가 난다.
5. 보안 > Client Secret 발급 → 코드 상태 ON → Supabase Kakao Provider에 입력.

### 3-2. 비즈니스 앱(비즈 앱) 전환 (당일 ~ 1일)
- 사업자등록번호가 **있으면**: 앱 > 비즈니스 정보에서 사업자 정보를 등록해 비즈 앱 전환.
- 사업자등록번호가 **없어도 가능하다.** [앱] > [일반] > [비즈니스 정보] > [개인 개발자 비즈 앱]에서 전환하며, 조건은 두 가지다:
  1. OWNER 개발자 계정의 **카카오 계정 본인인증** 완료
  2. 카카오비즈니스 통합 서비스 약관 동의

### 3-3. 동의항목 설정 및 검수 (영업일 3~5일)
현재 코드가 요청하는 동의항목은 `profile_nickname`(닉네임), `profile_image`(프로필 사진) 두 개뿐이다 (`src/views/login/ui/LoginView.tsx`).

1. 제품 설정 > 카카오 로그인 > 동의항목에서 닉네임·프로필 사진을 **필수 동의**로 설정.
2. 개인정보 동의항목은 **추가 기능 신청 → 심사**를 거쳐야 실서비스에서 쓸 수 있다. 신청 시 다음을 제출한다:
   - 서비스 회원가입 화면 캡처 (로그인 화면)
   - 수집 사유 설명
   - **개인정보처리방침 URL** — `https://실서비스도메인/privacy` (그래서 0절의 플레이스홀더를 먼저 채워야 한다)
3. 심사 소요: **영업일 기준 3~5일**. 심사에서 보는 것은
   - 회원가입 화면에서 실제로 받는 항목과 신청한 동의항목이 일치하는지
   - 개인정보처리방침에 해당 항목이 반영되어 있는지
   - 필수/선택 설정이 일관적인지
4. **반려 대비**: 반려되면 보완 후 재심사라 또 3~5일이 든다. 런칭일 **최소 2주 전**에 1차 신청한다.

### 3-4. 팀 멤버 / 테스트
심사 전에는 앱에 등록된 팀 멤버 계정으로만 로그인 테스트가 가능하다. 테스트할 카카오 계정을 팀 멤버로 미리 추가해 둔다.

## 4. 외부 API 쿼터 · 약관 (리드타임: 알라딘 문의 시 수일)

### 카카오 책 검색 API (`/api/books/search`)
- 쿼터: 다음(Daum) 검색 API는 **일 50,000건**이며, 책 검색을 포함한 각 세부 검색이 **일 30,000건**이다.
- 쿼터 상향은 제휴·협의가 필요해 별도 문의해야 한다. 앱 > 쿼터 메뉴에서 현재 적용 수치를 확인한다.
- 카카오 서비스 약관·운영정책을 따른다. 초기 트래픽에서 3만 건/일에 닿을 가능성은 낮지만, 검색어 입력마다 호출하면 빨리 소진된다 → 디바운스/캐싱 여부를 확인해 둔다.

### 알라딘 TTB Open API (`/api/aladdin/list`)
- **일반 TTB 회원: 일 5,000회 제한.** 기업(제휴) 회원은 무제한.
- **상업적 이용은 제한될 수 있다.** 알라딘 API는 비영리 개인 개발·정보 제공 목적 사용을 전제로 하며, 법인·단체의 상업적 이용은 사전에 알라딘에 문의해 정책을 확인해야 한다.
- 이용 조건으로 **출처 표기와 상품 링크가 요구된다**: "도서 DB 제공: 알라딘 인터넷서점(www.aladin.co.kr)" 표기 + 상품 클릭 시 알라딘 상품 페이지로 연결되는 링크.
  - 현재 `/about`, `/terms`, `/privacy`에 출처 문구는 넣어 두었다. **상품 상세에서 알라딘으로 나가는 링크는 별도 확인 필요.**
- 문의처: `ttb@aladin.co.kr` / 02-6913-2534. 수익모델이 있거나 법인이면 **런칭 전에 반드시 문의**한다.

## 5. 실기기 테스트 체크리스트 (리드타임: 반나절)

### 카카오톡 인앱 브라우저 — 가장 자주 터지는 곳
결과 페이지를 카톡으로 공유하면 받는 사람은 **카톡 인앱 브라우저**로 연다. 여기서 로그인이 막히는 사례가 한국 서비스에서 흔하다.

- [ ] 카톡 대화방에 `https://실서비스도메인/result/FIEW` 공유 → 썸네일(OG 이미지)·제목·설명이 뜨는지
- [ ] 인앱 브라우저에서 "카카오로 3초 만에 시작하기" → 흰 화면/무반응 없이 동의 화면까지 가는지
- [ ] 로그인 성공 후 `/auth/callback`을 거쳐 원래 페이지로 돌아오는지 (세션 쿠키가 인앱 브라우저에 남는지)
- [ ] 안 되면 대응: 인앱 브라우저 UA를 감지해 "외부 브라우저로 열기"를 안내하거나, 안드로이드는 `intent://` 스킴으로 크롬을 강제 실행하는 우회가 일반적이다. (구글 OAuth는 인앱 브라우저를 정책적으로 차단하지만, 이 서비스는 카카오 로그인만 쓰므로 그 케이스는 해당 없음)
- [ ] 인스타그램 인앱 브라우저에서도 동일 확인 (스토리 공유 유입 대비)

### 브라우저·기기
- [ ] iOS Safari — 하단 탭이 홈 인디케이터에 가리지 않는지, 100vh 스크롤 튐 없는지
- [ ] iOS Safari 프라이빗 모드 — `localStorage` 접근이 막혀도 앱이 죽지 않는지 (평가·위시리스트가 localStorage 기반)
- [ ] Android Chrome
- [ ] 데스크톱 Chrome (≥900px에서 `.bj-frame` 종이 레이아웃)
- [ ] 로그인 없이 `/test` → `/result/[typeCode]`까지 완주되는지 (유입 퍼널의 핵심 경로)
- [ ] 404 (`/없는주소`)와 에러 화면이 뜨는지

### 공유 메타 검증
- [ ] `https://실서비스도메인/robots.txt` · `/sitemap.xml` 응답 확인
- [ ] `https://실서비스도메인/result/FIEW/opengraph-image` 가 1200×630 PNG로 뜨는지
- [ ] 카카오톡 공유 시 캐시된 썸네일이 보이면 [카카오 캐시 초기화](https://developers.kakao.com/tool/clear/og) 사용
- [ ] Twitter/X, 슬랙, 페이스북 디버거로 카드 확인

## 6. 모니터링 · 분석 (권장만, 설치는 나중에)

코드 변경이 거의 없는 것부터. **지금 설치하지 않는다.**

| 도구 | 설치 비용 | 얻는 것 |
|---|---|---|
| **Vercel Analytics** | 대시보드 토글 + `@vercel/analytics` 1줄 | 페이지뷰·유입 경로. 유형 결과 공유가 실제로 유입을 만드는지 확인하는 최소 지표 |
| **Vercel Speed Insights** | 대시보드 토글 | 실사용자 Core Web Vitals |
| **Supabase Logs / Advisors** | 설치 불필요 | 쿼리 에러, RLS 경고. 이미 있다 |
| **Sentry** | 패키지 + 마법사 | 에러 스택. 사용자 리포트가 쌓이기 시작하면 도입 |

우선순위: Vercel Analytics → (유입이 생기면) Sentry. GA4는 동의 배너·개인정보 방침 추가 고지가 따라오므로 필요해질 때 결정한다.

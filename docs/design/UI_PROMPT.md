# BOOKJAK · Claude Code 작업 지시서 (UI_PROMPT)

이 파일은 클로드 코드가 UI를 만들 때 **매 작업마다 먼저 읽는** 규칙서다.
`tokens.css`, `components.css`와 함께 프로젝트 루트에 둔다.

---

## 0. 절대 규칙 (어기면 다시 작업)

1. **색은 semantic 토큰(`--color-*`)만 사용.** 컴포넌트/화면 코드에 hex를 새로 쓰지 않는다. primitive(`--p-*`) 직접 참조도 금지 — primitive는 tokens.css 안에서만 쓴다.
2. **그림자 금지.** `box-shadow`를 쓰지 않는다. 위계는 색과 보더로만 만든다.
3. **포인트 컬러는 주황 하나뿐.** UI에서 다른 vivid 색을 만들지 않는다. (리소 3색 팔레트는 일러스트 존 전용이며, 일러스트는 이 작업 범위 밖이다.)
4. **폰트 역할 고정.** 모든 정보성/본문 텍스트 = Pretendard. Wildgak은 닉네임·로고·희소도 뱃지에만.
5. **일러스트는 건드리지 않는다.** 이미지가 들어갈 자리는 아래 "일러스트 플레이스홀더" 규칙대로 빈 슬롯만 만든다.

---

## 1. 작업 순서 (반드시 이 순서로)

### STEP 1 — 아토믹 컴포넌트만 먼저
`components.css`의 `.bj-*` 클래스를 실제 프레임워크 컴포넌트로 래핑한다.
이 단계에서는 **화면을 조합하지 않는다.** 각 컴포넌트를 독립적으로,
props로 상태만 받는 순수 단위로 만든다.

만들 최소 단위(디자인시스템 번호와 1:1 대응):
- Button (primary / secondary / text / icon)
- Option (진단 선택지, selected 상태)
- Progress
- RarityBadge (common / rare / legendary)
- StatBar
- Chip
- Toggle, Check
- Input
- Card (공통 컨테이너)
- BottomNav + NavItem

각 컴포넌트는 `components.css`의 클래스만 붙이고, 자체 스타일을 새로 만들지 않는다.
스타일이 부족하면 → 임의로 CSS를 추가하지 말고 **먼저 물어본다.**

### STEP 2 — 컴포넌트 확정 후에만 화면 조합
STEP 1의 단위들이 승인되기 전에는 홈/결과/진단 화면을 만들지 않는다.
화면은 아토믹의 조합으로만 구성한다. 화면 단계에서 새 색·새 컴포넌트가
필요해 보이면, 만들지 말고 "이건 아토믹에 없다"고 보고한다.

---

## 2. 일러스트 플레이스홀더 규칙

일러스트는 사용자가 직접 넣는다. 코드에서는:
- 빈 슬롯 컨테이너만 만든다 (`aspect-ratio`로 비율만 잡고 배경은 `--color-surface`).
- 파일 경로는 `/assets/illust/{type-code}.png` 규칙을 그대로 쓴다 (예: `FIEW.png`).
- placeholder 안에 그라데이션·아이콘·더미 그림을 그려 넣지 않는다. 회색 톤 빈 박스 + 파일명 라벨이면 충분하다.

---

## 3. 컴포넌트 추가가 필요할 때

새 UI 패턴이 나오면 임의 생성하지 말고:
1. 기존 `.bj-*`로 표현 가능한지 먼저 확인
2. 불가능하면 → semantic 토큰만으로 새 `.bj-*` 클래스를 `components.css`에 **제안**하고 확인받는다
3. 승인 전에는 화면에 인라인 스타일로 우회하지 않는다

---

## 4. 품질 하한 (조용히 지킨다)

- 모바일까지 반응형
- 키보드 포커스 링 보임 (`:focus-visible`, 이미 tokens에 정의됨)
- `prefers-reduced-motion` 존중
